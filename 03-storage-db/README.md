# 03. Storage & DB — 데이터 계층

## 목표

스토리지·데이터베이스 서비스의 선택 기준을 세우고, RDS를 프로덕션 배치 원칙(프라이빗 서브넷, Multi-AZ)에 맞게 구성한다.

## 이론

- [ ] S3 심화: 버킷 정책 vs IAM 정책, 버전닝, 수명주기 규칙, 암호화 옵션(SSE-S3/KMS), 정적 호스팅, 사전 서명 URL
- [ ] 블록 vs 파일 vs 객체: EBS / EFS / S3 선택 기준
- [ ] RDS: Multi-AZ vs 읽기 복제본(목적이 다르다), 자동 백업·스냅샷·복원, 파라미터 그룹, 서브넷 그룹, 커넥션 관리(앱 커넥션 풀, RDS Proxy 개요)
- [ ] DynamoDB: 파티션 키 설계 원칙, 온디맨드 vs 프로비저닝, GSI/LSI, 어떤 워크로드에 맞는가
- [ ] ElastiCache 개요: 캐시를 두는 위치와 무효화 전략

## 실습 (labs/)

- 01 VPC의 프라이빗 서브넷에 RDS(MySQL 또는 PostgreSQL, single-AZ 소형) 배치
- 02의 웹서버(또는 임시 EC2)에서 보안 그룹 체인으로 DB 접속 확인
- S3 정적 웹사이트 호스팅 + 버킷 정책 구성
- DynamoDB 테이블 생성, CLI로 읽기/쓰기

⚠️ 비용: RDS는 시간당 과금. Multi-AZ는 비용 2배이므로 이론으로 이해하고 실습은 single-AZ로.

## 완료 기준

- apply → destroy 완주
